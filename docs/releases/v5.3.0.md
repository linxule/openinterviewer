# OpenInterviewer 5.3.0

Researchers can group studies into projects and export a whole project's
transcripts as one Markdown file. Prompted by
[@8888oukaouka-spec](https://github.com/8888oukaouka-spec)'s fork; see
[ACKNOWLEDGMENTS.md](../../ACKNOWLEDGMENTS.md). Standalone installations only
(Node and Cloudflare); hosted mode keeps the flat study list.

## Standalone projects

- Organize studies in collapsible projects or Ungrouped. Create and rename projects,
  move studies, or delete a project without deleting any studies or interviews.
- Grouping changes no study configuration, revision, consent, participant link,
  transcript or AI settings. Hosted workspaces retain the flat study list and do
  not request projects.
- **+ Study** saves the study first, then assigns it. If assignment fails, the
  saved study opens with a notice directing the researcher to the study list.
  There are no pending-assignment records or automatic paid requests.
- Export a project's raw transcripts as one Markdown file, with up to 500
  interviews total. Sources are read one study at a time; the project roster is
  rechecked at completion. A distinct project completion marker protects against
  partial downloads, including cuts immediately after a study's own marker.
  This is not a single cross-study point-in-time snapshot.
- Project listing supports 1,000 projects and 1,000 studies; names are trimmed,
  1–200 characters, without control characters. Duplicate names are allowed.

## Back up before upgrading; no in-place rollback to 5.2

Cloudflare applies forward-only application schema 3 with minimum reader 3.
A 5.2 build refuses a schema-3 workspace. Do not change its migration ledger or
reader minimum, and do not confuse application schema 3 with Wrangler class migrations.
Backup format 3 includes projects and memberships. Valid format-1/schema-1 and
format-2/schema-2 backups can be imported into an empty 5.3 recovery workspace;
project families are empty for those legacy imports.

Node rollback to 5.2 against a Redis database used by 5.3 is prohibited. Unlike
Cloudflare, Redis has no schema gate: a 5.2 build starts normally, ignores projects,
and a study deleted there leaves its project membership behind as an orphan record
(harmless to 5.3, which lists only live studies, but reported by the Redis inventory). Copy the Redis database before upgrading. Do not treat an older Node
build that starts successfully as compatible. Use a compatible forward fix.
If recovery requires a pre-upgrade backup, restore it to isolated storage and
reconcile later research records explicitly; never silently discard them.

See the [forward-only runbook](../operations/cloudflare-migration/RUNBOOK.md#projects-53-forward-only-upgrade).
No dependency versions change in this release round.
