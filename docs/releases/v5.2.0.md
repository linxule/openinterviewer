# OpenInterviewer 5.2.0

Analysis can now be written in the researcher's language. This completes the
5.1 language work, where analysis was always English.

## Analysis language

`ANALYSIS_LANGUAGE` sets the language of the model-written analysis for the
whole installation: `en` (the default), `zh`, `fr`, `ja`, `ko` or `es`.

- It covers each interview's analysis and the cross-interview aggregate, for
  every study, including English-only studies. Quotations stay verbatim in
  the participant's language.
- Exploration already answers in the language of the researcher's question.
- Analyses written before a change keep their language until they are run
  again.
- The study setup's Interview Languages section shows the current setting;
  `/api/config/status` reports it.
- An English installation's prompts are unchanged from 5.1.
  ([#93](https://github.com/linxule/openinterviewer/pull/93))

How to set it:

- **Cloudflare:** `npm run setup:cloudflare -- update --analysis-language zh`
  (with a deploy), or `--analysis-language` on `apply`. The installer keeps it
  in the receipt; `update --analysis-language en` returns to English.
- **Node:** the `ANALYSIS_LANGUAGE` environment variable; `npm run setup:check`
  reports an invalid value.

On Cloudflare the analysis queue reads the value from its own invocation, so
background analysis uses it too.

## Upgrade notes

- **Cloudflare:** `npm run setup:cloudflare -- update` deploys the new
  template, which adds the empty `ANALYSIS_LANGUAGE` var (English). No schema
  migration.
- **Rolling back to 5.1.x:** analysis returns to English. 5.1 ignores the
  setting; the receipt keeps it for the next upgrade. Nothing else changes.

## Verification

- `npm run check:cloudflare` (20 lanes) on the release commit.
- On staging, with the analysis language set to Chinese: a synthetic
  interview whose background analysis came back in Chinese, with verbatim
  quotations. Staging was then returned to English.
