# OpenInterviewer 4.1.0

A follow-up to [4.0.0](v4.0.0.md): participant sessions survive browser
storage failures, the participant link code stays out of every request header,
and the Cloudflare installer can rotate the administrator password.

## Participant sessions

- **Storage failures.** A participant whose browser refuses a storage write
  (for example when storage is full) carries on in memory instead of seeing
  "Failed to load study configuration". The link page hands over to consent
  with a full page load only when the whole session can be read back after it
  (session, study and transport, at the current store version).
  ([#52](https://github.com/linxule/openinterviewer/issues/52))
- **Link code privacy.** Participant links (`/p/<code>`) are now served by a
  static route through a rewrite, so the client router's `Next-Url` and
  `Next-Router-State-Tree` request headers never hold the code. In 4.0.0 they
  could, on browsers without session storage. Link URLs are unchanged.
- **Recovery.** A session held only in memory ends on a reload. The consent,
  interview and synthesis steps then tell the participant to open their link
  again, instead of showing "No study configured".

## Cloudflare installer

- `update --rotate-admin-password` replaces the administrator password in one
  secret upload, with no deploy. It checks the password like `apply` does and
  resumes if interrupted. Researcher sessions signed in before the rotation stay
  valid until they expire (up to 7 days); to end them after a leak, see
  [RUNBOOK.md](../operations/cloudflare-migration/RUNBOOK.md), administrator
  password.
- The project's own maintained instance is deployed with the installer from
  the owner's workstation. The `promote-cloudflare` CI job stays available as an
  optional CI-owned deployment for other installations
  ([INSTALLER.md](../operations/cloudflare-migration/INSTALLER.md)).

## Upgrade notes

- No configuration change on either target. Rebuild or redeploy to pick up
  the participant fixes; a Cloudflare installation updates with
  `npm run setup:cloudflare -- update`.
- Custom tooling that expected a `src/app/p/[token]` route: the link page is now
  `src/app/p/page.tsx`, reached by the rewrite in `next.config.js`.

## Verification

`npm run check:cloudflare` (the full release matrix) on the release commit,
a Codex review of the participant changes (its four minor findings are fixed),
and new browser tests on the Node and
Cloudflare targets. Those tests cover missing and full storage, a failed
client navigation, and request headers never carrying the link code.
