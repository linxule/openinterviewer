# OpenInterviewer 3.0.0 — save first, analyze later

This release collects the application changes since v2.0.0, including the
September dependency maintenance. It is a major release because participant
completion and follow-up API contracts changed. It is not only a dependency
patch.

## Participant and researcher workflows

- Finishing an interview saves the transcript before scheduling analysis.
  Participants receive a save confirmation and can leave while analysis runs.
  Failed saves remain retryable; researchers can recover pending or failed
  analysis individually or in a batch.
- Study setup now supports researcher-written thank-you text and Interviewer
  Manner instructions, alongside the existing coverage/depth control. Presets
  include Neutral, Warm, Formal, Plain language, and Concrete incidents.
- Analysis, aggregate synthesis, and follow-up generation use the study's
  configured provider and model. Interview records retain the conducting model
  and manner; analysis records the served model and the study revision used.
- Aggregate analysis is saved on the server, survives reopening the study, and
  includes citations that trace back through interview syntheses to transcript
  turns. Follow-up studies use that saved aggregate.
- Researcher reading, tabs, study setup, consent notices, and participant page
  layout were refined. The sample workspace includes evidence-trace examples.

## Upgrade notes

- `/api/synthesis` now accepts researcher previews only; participant calls
  return 403. Participant completion uses `/api/interviews/save`, which saves
  the transcript and derives analysis on the server rather than trusting a
  browser-supplied synthesis receipt. Custom clients must adopt this sequence.
- A completed interview can have `synthesis: null` while analysis is pending or
  failed. Export consumers must distinguish transcript completion from analysis
  completion. Researchers can request analysis through
  `POST /api/interviews/[id]/analyze?studyId=...`.
- Follow-up generation reads the server's saved aggregate. A browser-only
  aggregate from an older version must be regenerated before creating a
  follow-up study.
- Existing records remain readable without a backfill: legacy interviews with
  a synthesis are treated as analyzed. Plan upgrades from v2.0.0 around active
  collection; old participant tabs use the previous completion protocol. Do
  not reload a tab containing unsaved participant responses.
- Node.js 24.19 or newer is required. Typechecking uses TypeScript 7; the
  TypeScript 6 API alias remains necessary for Next.js and ESLint tooling.
  ESLint stays on v9 because v10 currently fails with the supported plugin stack.

## Reliability and dependency maintenance

Analysis claims and retry counts are atomic, corrupt stored records are
distinguished from storage outages without modifying them, and provider response
validation preserves JSON values and requires served-model provenance. Regression
coverage now exercises save, deferred analysis, recovery, aggregate citations,
and export against disposable Redis with synthetic provider HTTP responses.

Provider SDKs, React, react-markdown, Upstash, test tooling, and transitive
dependencies were updated. Weekly grouped Dependabot coverage now includes npm
and GitHub Actions. The complete npm audit and GitHub security-alert check found
zero vulnerabilities during release preparation on September 14, 2026.

The release gate includes lint, typecheck, unit/setup tests, standalone/direct,
standalone/Gateway and hosted builds, browser workflows, Redis crash cuts,
adversarial tests, and a Vercel preview. The separate paid live-provider smoke
was intentionally omitted for this dependency update; fixture tests do not
establish live model availability or hosted OAuth onboarding behavior.
