# OpenInterviewer 5.0.0

This release extends OpenInterviewer from collecting and summarizing interviews
to revisiting a study's evidence. It also closes lifecycle and workflow gaps
found while examining real researcher feedback.

## Research exploration

- A saved **Explore** workspace asks natural-language questions of the selected
  raw transcripts, including pending or failed individual analyses.
- Dataset selection names revisions, interviews and deterministic recorded
  profile filters. Missing, refused, vague, legacy or conflicting fields stay
  unknown. No demographic inference or silent sampling.
- Answers retain their exact source manifest and served-model provenance.
  Findings distinguish supporting, challenging and uncertain quotations.
  Matching a quotation verifies its location, not the truth of an interpretation.
- Question attempts are idempotent and durable. One attempt means one provider
  request, with no automatic retry, fallback or repair request. Uncertain
  execution requires an explicit new attempt. Save-only signed receipts recover
  unsaved results for 24 hours without another model call.
- All existing provider transports are supported. Every source's original
  fixed-provider commitment and transport disclosure is checked before use.
- Aggregate analysis can use explicit historical scope; follow-up generation
  retains that scope. The original default remains current-revision analysis.

## Researcher control

- Settings adds a two-confirmation **Danger Zone** for deleting populated
  studies and associated live-store interviews, links, aggregate and notebook.
  Redis cleanup is bounded and resumable; hosted cleanup preserves its durable
  cross-database journal. Late writes are fenced.
- Pause/resume preserves the revision and existing active links. Unchanged
  saves no longer invalidate participant authority.
- New, edit and duplicate actions have separate intent and session drafts.
  Edits reload canonical data, stale drafts need review, and duplicates copy
  configuration only. Preview remains saved-version-only.
- Dashboard selection races, stale errors and completed create-key reuse are
  fixed. Study-scoped ZIP export includes raw records, aggregate and notebook.
- Newly saved interviews snapshot their original collection configuration.
  Analysis retries use that context rather than relabeling historical fields.

## Updated provider defaults

New Claude studies default to `claude-sonnet-5-5`; new OpenAI studies default
to `gpt-6.1-sol`. Existing saved studies and participant commitments keep their
configured IDs. GPT-6 Sol and lower-cost GPT-6 Luna are available choices;
legacy model IDs remain accepted.

The adapters retain native structured output and apply model-specific reasoning
parameters. On GPT-6.1 Sol, the lower-reasoning setting uses `low` because the
model does not support `none`; Sonnet 5.5 uses `between_tools` when extra
reasoning is disabled. Vercel Gateway maps Sonnet's native ID to
`anthropic/claude-sonnet-5.5` without changing the stored provider-native ID.

## Limits and data boundaries

An exploration request uses at most 100 interviews and 256 KiB of exact
provider-facing corpus, with a separate 320 KiB complete-prompt bound; a study
retains at most 500 question attempts. Dataset inspection is
bounded at 1,000 interviews. Oversized requests are refused before model use.
Researcher exploration budgets are 20 requests/session/hour and
100 requests/workspace/day on standalone installations. Hosted limits remain
researcher-scoped. Checking or saving an existing result makes no provider call.

Deletion affects the installation's live store, not external downloads,
operational backups or already-started provider requests. Legacy unindexed
consent records contain identifiers/hash only and expire after four hours;
new records have study-owned cleanup indexes.

## Upgrade and rollback

Cloudflare applies schema migration 2 for the notebook. It requires reader
version 2: older releases intentionally refuse an upgraded workspace rather
than omit notebooks from export, backup or deletion. This is a forward-fix
release, not a compatible in-place rollback to 4.x. Preserve a verified
pre-upgrade backup and its matching old release before upgrading, and rehearse
restore in isolated staging. Restoring an old backup also loses records
collected since that backup; never run both versions against the same live
workspace.

Operational backup format 2 includes notebooks. The new build accepts legacy
format-1/schema-1 backups; older builds cannot import format 2. Node Redis has
new notebook and deletion-fence records too: use the new build for cleanup and
exports rather than rolling back over those records.

No new credentials or services are required. Update through the existing
Cloudflare installer after the clean-commit release matrix succeeds. Deployment,
public release publication and real-provider compatibility are separate from
fixture verification. The combined check writes its commit- and bundle-bound
receipt to `dist/cloudflare/artifact/receipt.json`; deployment verifies that
receipt rather than relying on this prose.

## Provider verification

On 2026-09-29, two authorized direct OpenAI smoke requests using synthetic
interviews passed: individual synthesis and study exploration. Both requested
and served `gpt-6.1-sol`; each allowed one HTTP attempt with automatic retries
disabled. No participant content or store was used. This establishes response
compatibility and provenance, not research quality. Claude Sonnet 5.5 is covered
by native request-serialization and refusal regressions, not a live Anthropic
smoke. See the [model contract](../operations/model-contract-2026-09-29.md).
