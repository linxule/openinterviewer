# OpenInterviewer 4.0.0 — Cloudflare standalone

This release adds a second self-hosting target: a standalone installation on
Cloudflare Workers, with no Redis and no Vercel. The Node/Vercel target and the
hosted mode keep working as before. It is a major release because the project's
own maintained instance moves to Cloudflare, participant links and the
participant hand-over changed, and a new provider transport records what
participants were told.

## Cloudflare standalone

- One installation is a Worker, a SQLite Durable Object workspace (with a
  jurisdiction, `eu` recommended), a Queue for background analysis and, if
  chosen, a Cloudflare AI Gateway. `npm run setup:cloudflare` plans, installs,
  resumes, updates, verifies and rolls back installations; it never deletes
  anything. See [INSTALLER.md](../operations/cloudflare-migration/INSTALLER.md).
- Operators get maintenance states (open, draining, frozen, recovery),
  operational backup and import, and point-in-time restore through
  `npm run operator:cloudflare` ([RUNBOOK.md](../operations/cloudflare-migration/RUNBOOK.md)).
- Moving an existing Node/Vercel deployment is described in
  [TRANSITION.md](../operations/cloudflare-migration/TRANSITION.md), including
  how to cut off the old deployment's database access.
- Workers Paid is recommended: the Free plan's 10 ms CPU limit per request is
  too little for this application.

## Providers

- A Cloudflare installation can bind all four provider keys (Gemini, Claude,
  OpenAI, OpenRouter); every study picks its provider and model.
- Optional Cloudflare AI Gateway transport (`--ai-transport cloudflare-gateway`):
  provider requests go through the installation's own gateway with logging and
  caching off, one attempt and provider keys required. Participants are told
  before they consent, including that Cloudflare may process responses outside
  the EU; a consent given for direct transport does not cover the gateway.
- The default Gemini model for new studies is `gemini-3.8-flash`.

## Fixes that also affect v3.0.0

Found by paid live tests during release; upgrade if you use these providers:

- **Claude:** every structured request (interview turns, analysis, aggregate,
  follow-up) was refused by the Anthropic API, which does not accept `minimum`,
  `maxItems` or nullable enums in structured-output schemas. Claude now receives
  a compatible schema; the application's own validation still enforces every
  bound.
- **OpenRouter:** every analysis failed as "did not identify the upstream
  provider", because OpenRouter stopped reporting routing attempts on
  single-endpoint routes. The served upstream is now read from the selected
  endpoint.

## Participant privacy

- The participant link page no longer sends its URL, which holds the link
  code, in request headers (`Referrer-Policy: no-referrer`, and a full page
  load to consent instead of a client-side navigation where the session can be
  persisted).
- A participant never sees an interview step on a page that is about to be
  replaced; delayed navigations no longer discard typed answers.

## Upgrade notes

- Node/Vercel deployments need no configuration change. Rebuild to pick up the
  provider fixes.
- Custom clients of the participant link exchange are unaffected; the consent
  request may carry `disclosedTransport` (a missing value means `direct`).
- Known follow-ups: [#52](https://github.com/linxule/openinterviewer/issues/52)
  (participant sessions when browser storage writes fail).
