# OpenInterviewer 5.4.0

Participants can dictate answers on their own computer without the recording
leaving it, and every study export now includes analysis files for AI coding
tools and spreadsheets. No database schema change.

## On-device voice input

A fourth study voice mode, **On the participant’s computer (desktop Chrome
only)** (`device`), lets the participant's browser turn speech into text locally.
Like the other voice modes, text appears in the answer box for review and is
never sent automatically. Inspired by Yinghua's
([@8888oukaouka-spec](https://github.com/8888oukaouka-spec)) participant-microphone
idea in her fork, credited in [5.1.0](v5.1.0.md) and
[ACKNOWLEDGMENTS.md](../../ACKNOWLEDGMENTS.md); this local-only implementation is
not authored by her or imported from the fork.

- Desktop Chrome 139+ exposes local speech recognition. The microphone appears
  only if the selected language's local pack is available, downloadable or
  downloading. Phones, Safari, Firefox stable and unsupported devices show no
  microphone; participants type instead.
- The first press can ask the browser to install a speech pack (about 60 MB).
  A localized preparation note appears; typing and Send remain available. Once
  ready, press the microphone again to start (no surprise recording after a
  slow download).
- Every recognizer started in device mode has `processLocally = true`. There is
  no fallback to browser cloud dictation or installation transcription.
  `language-not-supported` and `service-not-allowed` disable the mic for that
  participant session, with a short localized note.
- Consent presents locality as the browser's promise, not ours: the browser
  turns speech into text on this computer and says the recording stays there;
  the study receives only the text the participant sends. OpenInterviewer cannot
  verify what the browser does internally. The submitted **text** still
  follows the study's usual AI interview and storage terms.
- Works with standalone and hosted studies without server transcription
  credentials, capability or readiness changes. `/api/transcribe` still accepts
  only `installation`. Changing voice mode advances the study revision and
  invalidates older participant authority. Markdown exports describe the mode
  offered at collection, not whether the microphone was used.

## Analysis files in the study export

Study and workspace ZIP downloads now include an `analysis/` folder for AI coding tools and spreadsheets. No new export button or third-party adapter is required.

- `README.md` defines every field and repeats the Markdown export’s consent/provider sharing warning.
- `interviews.jsonl` holds one interview per line with its saved collection protocol, consent and provider records, synthesis, profile and verbatim turns.
- `interviews.csv` offers an interview-level table, including dynamic profile columns labeled from the newest interview.
- `turns/NNN.csv` provides a turn table per interview, keeping export memory bounded. Turn indices match analysis citations: skipped system messages leave gaps.
- `profile_fields.csv` preserves each profile value’s historical label and extraction status.

CSV files use UTF-8 with BOM and CRLF. Formula-like text receives a protective apostrophe; JSONL is the source for verbatim quotations. Missing historical configuration remains missing, never reconstructed from the current study. Per-interview Markdown timestamps in the ZIP now use ISO UTC.

Node and Cloudflare produce the same file contents. Cloudflare reads the same captured snapshot in bounded passes, and the archive is finalized only after all files and the final sequence check succeed. Existing raw JSON, Markdown, summary CSV, aggregate and notebook exports remain included.

Before sharing these files with another AI service, check each participant’s recorded provider commitment. Exporting data does not change that promise.

## Upgrade and rollback

No database schema, environment variable or binding changes; deploy as a
code-only release.

**Rollback to 5.3 refuses device-mode studies.** 5.3 does not know
`voiceInput: 'device'` and fails closed: saving such a study returns 400,
participant-context resolution and link generation 409 (`STUDY_REQUIRES_RESAVE`),
and the canonical-study loader 503. Nothing is converted to cloud dictation or
deleted. Before rolling back, stop collection and save affected studies with
voice **Off** on 5.4 (this advances the revision, so issue new links).
Interviews collected under device mode keep it in `collectionConfig`; 5.3's
Markdown export omits their voice line and operations that validate historical
configuration can refuse them. Prefer rolling forward.
